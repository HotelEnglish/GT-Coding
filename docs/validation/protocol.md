# 可审计扎根理论工作台 · MVP 验证门（Validation Gate）

> **状态：** 生效中。依据 `docs/plans/2026-10-22-auditable-gt-workbench-v2.md` Phase 5 落地。
>
> **总原则：** 本协议多次重申——任何评审都**不预设唯一的"正确编码树"**。扎根理论的说服力来自证据链可回放与决策过程可审计，而不是来自与某棵参照树的吻合度。

---

## 1. 目的与适用范围

本验证门用于判断当前研究工作台（进程内异步分析 + 证据溯源 + 研究者决策 + 审计导出）是否达到"可让真实研究者放心使用"的最低标准。

**在验证门全部通过之前：**

1. 不新增第二套方法论 profile（constructivist / classical 等保持未启用）；
2. 不改动账号 / 计费 / 管理相关模块（ADR 0004、ADR 0005 冻结范围）；
3. 不把任何一份真实语料推入功能扩展。

## 2. 数据准备门槛（去标识核查单）

在试点（pilot）开始前，数据的**_HANDLERS_（处理人）与 _RESEARCHER_（研究执行人）必须共同签署以下核查单**。签署文件存放于本地（`docs/validation/signed-checklist.md` 即可，不入库真实数据）。

| # | 核查项 | 要求 | 通过 |
|---|--------|------|------|
| D1 | 直接标识符 | 姓名、昵称、邮箱、电话、微信号/QQ 号、身份证、病历号、工号、平台账号 ID 全部替换为 `R01…Rnn` 之类受访者编号 | ☐ |
| D2 | 地理标识 | 省市以下信息（含街道名、门店名、GPS、车牌）删除或泛化到"某市"级别 | ☐ |
| D3 | 机构标识 | 公司可识别组合（"某某骑手站点 + 站长姓名"）删除或泛化 | ☐ |
| D4 | 日期标识 | 精确到日的日期（生日、入职日）如与结论无关则模糊化为"入职约半年" | ☐ |
| D5 | 原件隔离 | 原始录音 / 原始访谈稿**不进入本仓库、不上传 issue、不上传云盘公开目录**；仅保留在研究者本人的加密磁盘区 | ☐ |
| D6 | 转写一致性 | 已核对"去标识稿"与"原始稿"语义无损（改写处仅限 D1–D4 要求） | ☐ |
| D7 | 二次凝视 | 处理人间隔 ≥ 24 小时后重读一遍去标识稿，确认无遗漏标识符 | ☐ |

> 违反 D5 的扩散后果不可逆，因此 D5 具有否决权：不同时满足，试点不得开始。

## 3. 知情同意与服务商合规门

### 3.1 知情同意（数据提供处）

参与访谈/社区文本的研究对象其知情同意书中，**必须**包含以下任一授权表述（按当地研究伦理要求裁剪）：

1. 同意研究对话文本被**计算机辅助软件处理**（含 AI 提示与建议生成）；
2. 该处理在**保持引语逐字**的前提下进行，且该引语仅用于研究分析；
3. 研究者可在**任何时点**拒绝某条 AI 建议（本工作台 UI 天然支持该权利）。

### 3.2 服务商合规门（事件前置门）

当前 `AI_PROVIDER=development` 为**离线模拟**，不发出任何网络请求，本门自动视为通过。

在接入任何真实模型服务商**之前**，须在 `docs/validation/provider-gate.md` 记录并确认：

1. **发送范围**：仅发送研究者已按第 2 节去标识的文本片段（segment），不发送片间上下文以外的信息；
2. **密钥位置**：API Key 仅存于 `server/.env`（`.gitignore` 已排除），严禁写入前端或审计导出；
3. **审计透明**：每次真实的 `ModelRun` 记录 provider / model / promptVersion / token 数 / 时延，研究者可随时在审计导出中查看（但**永远看不到密钥**）；
4. **数据保留**：记录所服务商的数据保留与训练使用政策链接；如政策不符合"研究数据不入训练集"的原则，须在文档中显式签署例外。
5. **撤回路径**：若研究者中途撤回同意，去标识稿可删除，而 DB 中的版本与决策事件将随之级联删除（删除操作需在协议中显式记录）。

## 4. 试点（pilot）流程

1. **样本准备**：选择 ≥ 2 份去标识材料，覆盖不同长者/类型（如一份访谈 + 一份社区帖文），每份 500–5000 字符为宜。
2. **第一轮（研究者本人）**：研究者完整走一次「上传 → 运行 → 逐条评审（accept/edit/reject/defer）→ 备忘录 → 饱和度自评 → 审计导出」。
3. **第二轮（双评，双盲）**：两位评审（可含研究者本人以外的人）只获得两样东西：
   - **审计导出 JSON/CSV**（含版本、偏移、哈希、决策事件、模型元数据）；
   - **对应去标识稿原文**（用于证据核对）。
   评审**看不到**彼此的记录，也看不到服务端上下文，只能依据档案独立填写 `pilot-scorecard.csv`。
4. **缺陷记录**：按下节规则，只记录在 `docs/validation/pilot-scorecard.csv`。

## 5. 双评双盲评审协议（评分维度）

五个维度等于一次试点「缺陷扫描面」，评分必须来自**具体可引用的档案记录 id**（assignment id / memo id / run id），不接受"感觉不错"类表述。

| 维度 | 问题 | 通过线 |
|------|------|--------|
| **证据准确性** | 每条 accepted/edited 建议的引语能否在去标识稿中按版本 + UTF-16 偏移精确锚定且逐字一致？ | 试点内**零无效证据链接**（程序化校验 + 双评人工点验双重确认） |
| **代码区分度** | 相邻代码是否因语义微差而不合逻辑地重复？接受/拒绝理由是否解释区别？ | 评审人认为每对"疑似重叠代码"都有书面理由 |
| **反例处理** | 饱和度自评的"未决问题 / 反例"两个字段是否被认真使用？反例是否回写为新的决策/备忘？ | 每份材料的档案中至少出现过一次反例驱动的动作，或书面说明"无反例" |
| **AI / 人归属** | 档案（含导出）中是否存在任何一条 AI 建议被误写为研究者原创？edit 后的 AI 原文是否全部可回访？ | **零混同**：随意抽 10 条，每条 origins/status/originalQuote 可回放且与 UI 一致 |
| **修改工作量** | 从 AI 原始建议改为研究者定稿，平均需要几步、几类修改？ | 评审写明"预计正式研究中可能的返乘工作量（低/中/高）"，作为后续 provider/prompt 决策的核心输入 |

> 明确排除项：**不**为企业试点设定"与专家树匹配率 ≥ X%"的目标。匹配率本身是研究性输出，不是工程通过线。

## 6. 通过标准（全部满足才放行）

1. **零无效证据链接**：程序化校验（对档案 JSON 逐条重算内容哈希与偏移命中）结果为 0 失败，且两位评审各自人工点验 ≥ 10 条记录全为命中；
2. **幂等重放通过**：以同一 `Idempotency-Key` 重复请求同一分析 ≥ 2 次（含一次在 provider 失败后重试），服务端 DB 中该 key 对应的 `AnalysisRun` 行数不增加、不重复扣任何成本；
3. **导出再导入通过**：把 JSON 导出物重新读入校验脚本（后端提供 `scripts/validate-audit.ts` 或等价），schema 合法、各哈希可重算一致、无任何服务商密钥字段；
4. **双评审签认**：本文件末尾签署区被两份签名（Name + Date）覆盖，五个维度全部达到"通过线"；
5. **旧版警示可见**：若存在 legacy 产物，审计导出的头部 `legacy.warnings` 包含 `legacy: provenance incomplete`。

## 7. 缺陷记录规则

- 记录文件：`docs/validation/pilot-scorecard.csv`（列定义见该表头）。
- **红线**：任何缺陷描述**不得包含**去标识稿的原文句子（防止语料被推送到公开 issue 系统）。描述时只允许引用 id + 抽象描述（例：`分配 a1b2 的引语在稿件中不存在`）。
- 与本仓库 git 提交同步时可包含该 CSV；**不得**为缺陷记录新建 GitHub issue 并粘贴语料。
- 每条缺陷必须有 `status`（open / fixed / wontfix）与 `disposition`（一句话处置说明），`wontfix` 需给出研究侧理由。

## 8. 全部通过后

验证门通过后解锁：

1. 新增第二套方法论 profile；
2. 服务商合规门签署后的真实 provider 接入（`AI_PROVIDER` 非 development）；
3. 启动 ADR 0005 的 Casdoor 身份方案迁移评估；
4. legacy 编码模块（含 UI 快照、`/api/coding/*` stub）的删除决策。
